01 문제

triage는 구조적으로
불가능한 게임이다

294건/일CI 실패 티켓 발생량 (사내 실측)
20–30분티켓 1건 정밀 triage 시간
3–4시간당번의 하루 실제 공급
정밀 triage 커버리지 ~3%필요: 일 122시간 · 공급: 3~4시간

나머지 97%는 방치·지연. 게다가 3개월 로테이션마다 당번의 판정 노하우가 리셋된다 — 지식이 개인에게만 쌓이고 조직에 안 남는다.

CI 실패

신뢰도 0–100 → 배정
>80 담당자 · ≤80 당번 → Jira 해결
Done → ingest
↑ query  ·  ↓ 축적(ingest)

해결된 이슈가 case-log로 축적되어 다음 같은 유형의 신뢰도를 올린다.

핵심 차이는 “분류가 지식을 남기는가” 하나다.

04 신뢰도 게이트 · human-in-the-loop

확신은 자동, 애매함은 사람

신뢰도 > 80

담당자 자동 배정

vault 노트의 owner로 Jira assignee 지정 + 근거 댓글 + In Progress 전이. 당번 손을 안 거친다.

신뢰도 ≤ 80

당번(sheriff) 큐

실패 로그·과거 사례·판정 근거가 이미 첨부된 상태. 당번은 판정이 아니라 확인만.

추천 후보를 Gerrit 마지막 커미터 + WIKI 담당자 두 신호로 융합해 제시.

근거 없는 고신뢰는 금지 — 신뢰도는 wiki 증거 강도에 비례한다. 오배정을 막는 설계.

05 스스로 정리하고 교정한다

지식베이스가 깨끗하게 학습한다

중복 정리

같은 실패 서명의 티켓이 여러 개 와도 case-log는 하나로 — 재발 카운트만 올린다. near-duplicate 오염 방지.

ingest dedup

재해결 교정

reopen 후 다시 고치면 교정된 해결을 버전으로 재기록하고 이전 기록을 supersede. 틀린 지식을 안 남긴다.

reopen re-ingest

피드백 감점

담당자가 “원인 일치/불일치”를 판정 → 불일치 누적 노트는 검색에서 감점·정리 후보. 스스로 솎아낸다.

feedback / lint

대부분의 RAG는 지식을 쌓기만 한다 — SVP는 틀린 것을 걷어낸다.

06 데모

“Jira만 쓰면 앱이 알아서 배운다”

  • ①아는 이슈가 유입되면 수 초 내 담당자에게 자동 배정 + 근거 댓글.
  • ②담당자가 Jira에서 Done 처리 → 앱이 감지하고 case-log에 실시간 기록.사람은 늘 하던 대로 Jira만 쓴다 — 앱에 해결 버튼이 없다.
  • ③모르는 이슈는 당번에게 (자동화가 아는 척하지 않는다).
  • ④같은 이슈가 재발하자 이번엔 자동 배정 — 쓸수록 배정률이 오른다.이게 이 도구의 존재 이유 (핵심 컷)
07 효과

커버리지 3% → 100%

3% → 100%
전량 발생 수 초 내 1차 분류 (실패 로그·과거 사례 자동 첨부)
일 → 분
배정 리드타임 — 당번 창구 대기(최대 1일)에서 폴링 주기로
연 ~470h
당번 시간 절감 (보수 추정 · 실측은 dry-run으로 확정 예정)
조직 기억
3개월마다 리셋되던 노하우가 vault에 영구 축적 — 온보딩 비용 소멸

LLM 비용은 모델 tier·프롬프트 캐싱으로 관리 — 절감이 비용을 상회하도록 설계.

  • 사내 Jira · Jenkins 실연동 검증 — 중계빌드에서 실패 TC 구간 로그 자동 첨부

  • 운영 vault는 사내에 분리 — 비밀정보는 서버 .env에만, 클라이언트 무자격증명
